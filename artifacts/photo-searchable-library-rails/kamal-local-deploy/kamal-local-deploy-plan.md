# Local Kamal Deploy Loop — Implementation Plan

*Created: 2026-10-02*

**Goal:** Make `bin/kamal deploy -d local` genuinely runnable — a full
Kamal orchestration loop against this macOS machine: SSH-to-localhost, a
throwaway registry, kamal-proxy on :80, the Rails app behind Thruster, and the
sidecar accessory — verified with a smoke test, then documented in the README.

**Architecture:** `config/deploy.local.yml` (machine-specific, gitignored,
generated by the harness) overlays the base `config/deploy.yml` with
`servers.web: [localhost]`, `ssh.user: $USER`, and the sidecar accessory host
`localhost` + port `9090:9090`. A throwaway `registry:2` container on `:5555`
is shared by the local build and the localhost "server". `script/kamal-local.sh`
orchestrates preflight → registry → build/push → `bin/kamal deploy -d local`
(which boots proxy + app) → `bin/kamal accessory boot sidecar -d local` →
smoke through :80 → teardown.

**Tech Stack:** Rails 8.1, Kamal 2.12, Thruster (in-image), Docker/BuildKit,
macOS (Remote Login/sshd), throwaway `registry:2`.

**Source:** `kamal-local-deploy-inception.md` (this dir).

## Tasks

### Task 1: Enable and verify SSH-to-localhost (prerequisite, no commit)

Kamal deploys by SSHing to the target. For a local run the target is this
machine, so `sshd` must answer on `localhost` with key auth for the current
user. This task is a one-time machine setup; there is nothing to commit.

**Files:**
- None (machine configuration)

- [ ] **Step 1: Enable Remote Login**

On macOS, run:

```bash
sudo systemsetup -setremotelogin on
```

If `systemsetup` is unavailable, use System Settings → General → Sharing →
Remote Login → On instead. No output means success.

- [ ] **Step 2: Verify sshd is listening**

Run:
```bash
sudo launchctl load -w /System/Library/LaunchDaemons/ssh.launchd 2>/dev/null || true
lsof -nP -iTCP:22 -sTCP:LISTEN
```
Expected: `lsof` lists `sshd` (or `ssh-agent`/`sshd` launchd job) on `:22`.
If nothing listens, retry Step 1 and re-check.

- [ ] **Step 3: Authorize the current user's key**

Run:
```bash
ssh-copy-id localhost
```
If `ssh-copy-id` prompts for a password, enter your macOS login password.
Expected: prints `Now try logging into the machine, with: ssh 'localhost'`.

- [ ] **Step 4: Verify key auth without a password prompt**

Run:
```bash
ssh -o BatchMode=yes -o ConnectTimeout=5 localhost true && echo "SSH LOCALHOST OK"
```
Expected: prints `SSH LOCALHOST OK`. If it fails, your key is not in
`~/.ssh/authorized_keys` — repeat Step 3.

- [ ] **Step 5: Verify `RAILS_MASTER_KEY` is available**

Run:
```bash
[ -n "${RAILS_MASTER_KEY:-}" ] && echo "RAILS_MASTER_KEY set" || echo "RAILS_MASTER_KEY MISSING"
```
Expected: `RAILS_MASTER_KEY set`. If missing, export it from your password
manager (the value must match the one used to encrypt
`config/credentials/production.yml.enc`). Do not print the value.

### Task 3: Create the harness script

**Files:**
- Create: `script/kamal-local.sh`

- [ ] **Step 1: Write the script**

```bash
#!/usr/bin/env bash
# Local Kamal deploy loop for macOS. Exercises the full Kamal orchestration
# against this machine: SSH-to-localhost, throwaway registry on :5555,
# kamal-proxy on :80, the Rails app, and the sidecar accessory.
#
#   script/kamal-local.sh preflight  # check ssh / ports / RAILS_MASTER_KEY
#   script/kamal-local.sh up         # registry -> build/push -> deploy -> accessory -> smoke
#   script/kamal-local.sh smoke      # re-run the smoke check against a running stack
#   script/kamal-local.sh status     # show the stack
#   script/kamal-local.sh down       # remove app, accessory, proxy, registry, volumes
set -euo pipefail

SERVICE="photo_searchable_library_rails"
REGISTRY_HOST="localhost:5555"
REGISTRY_CONTAINER="kamal-local-registry"
SIDECAR_IMAGE="$REGISTRY_HOST/${SERVICE}_sidecar"
LOCAL_CONFIG="config/deploy.local.yml"

info() { printf '\n==> %s\n' "$*"; }
die()  { printf 'ERROR: %s\n' "$*" >&2; exit 1; }

require_env() {
  if [ -z "${RAILS_MASTER_KEY:-}" ]; then
    die "RAILS_MASTER_KEY is not set. Export it from your password manager, then re-run."
  fi
}

preflight() {
  require_env

  info "SSH to localhost"
  ssh -o BatchMode=yes -o ConnectTimeout=5 localhost true 2>/dev/null \
    || die "Cannot SSH to localhost. Enable Remote Login (System Settings > General > Sharing > Remote Login) and authorize your key: ssh-copy-id localhost"

  info "Port 80 (kamal-proxy)"
  if lsof -nP -iTCP:80 -sTCP:LISTEN >/dev/null 2>&1; then
    die "Port 80 is already in use; stop the other service first (it would collide with kamal-proxy)."
  fi

  info "Port 5555 (throwaway registry)"
  if lsof -nP -iTCP:5555 -sTCP:LISTEN >/dev/null 2>&1; then
    die "Port 5555 is already in use; stop the other service first."
  fi

  info "Port 9090 (sidecar accessory)"
  if lsof -nP -iTCP:9090 -sTCP:LISTEN >/dev/null 2>&1; then
    die "Port 9090 is already in use. The dev stack (bin/dev-docker) must not run alongside this loop."
  fi

  command -v docker >/dev/null || die "docker is required"
  info "Preflight OK"
}

write_config() {
  cat > "$LOCAL_CONFIG" <<YAML
# Generated by script/kamal-local.sh — machine-specific, do not commit.
# Merges over config/deploy.yml for every bin/kamal ... -d local invocation.
servers:
  web:
    - localhost

ssh:
  user: ${USER}
  port: 22

accessories:
  sidecar:
    host: localhost
    port: "9090:9090"
YAML
}

ensure_registry() {
  if ! docker inspect "$REGISTRY_CONTAINER" >/dev/null 2>&1; then
    info "Starting throwaway registry on :5555"
    docker run -d --name "$REGISTRY_CONTAINER" --restart=no -p 5555:5000 registry:2
  else
    info "Registry container already present"
  fi

  info "Waiting for registry /v2/"
  for i in $(seq 1 30); do
    if curl -fsS "http://$REGISTRY_HOST/v2/" >/dev/null 2>&1; then
      echo "    ready after ${i}s"
      return 0
    fi
    sleep 1
  done
  die "Registry at $REGISTRY_HOST never came up; check: docker logs $REGISTRY_CONTAINER"
}

push_sidecar() {
  info "Building sidecar image (amd64 emulation; pulls torch, allow several minutes)"
  docker build --platform linux/amd64 -f sidecar/Dockerfile -t "$SIDECAR_IMAGE" .
  info "Pushing sidecar image to $REGISTRY_HOST"
  docker push "$SIDECAR_IMAGE"
}

deploy_app() {
  info "bin/kamal deploy -d local (builds+pushes app image, boots proxy + app)"
  bin/kamal deploy -d local
  info "Booting sidecar accessory"
  bin/kamal accessory boot sidecar -d local
}

wait_up() {
  info "Waiting for app /up through the proxy on :80"
  for i in $(seq 1 90); do
    if curl -fsS "http://localhost/up" >/dev/null 2>&1; then
      echo "    up after ${i}s"
      return 0
    fi
    sleep 1
  done
  die "App never answered /up. Check: bin/kamal app logs -d local"
}

wait_sidecar() {
  info "Waiting for sidecar /v1/status (models loaded) on :9090"
  for i in $(seq 1 300); do
    if curl -fsS "http://localhost:9090/v1/status" 2>/dev/null \
      | python3 -c "import json,sys; sys.exit(0 if json.load(sys.stdin).get('ok') else 1)" 2>/dev/null; then
      echo "    ready after ${i}s"
      return 0
    fi
    sleep 2
  done
  die "Sidecar never reported ready. Check: bin/kamal accessory logs sidecar -d local"
}

smoke() {
  wait_up
  wait_sidecar

  info "Smoke: catalog overview"
  curl -fsS -H "Accept: application/json" "http://localhost/catalog/overview" \
    | python3 -c "import json,sys; d=json.load(sys.stdin); print('    sources:', [s['kind'] for s in d['sources']])"

  info "Smoke: upload test/fixtures/tiny.jpg"
  RESP=$(curl -fsS -F "file=@test/fixtures/tiny.jpg;type=image/jpeg" "http://localhost/assets/upload")
  JOB_ID=$(printf '%s' "$RESP" | python3 -c "import json,sys; print(json.load(sys.stdin)['job_id'])")
  echo "    job_id=$JOB_ID"

  info "Smoke: wait for import job (first run may download weights)"
  for i in $(seq 1 180); do
    STATUS=$(curl -fsS "http://localhost/jobs/$JOB_ID" \
      | python3 -c "import json,sys; print(json.load(sys.stdin)['status'])")
    if [ "$STATUS" = "done" ]; then
      echo "    done after ${i}s"
      break
    fi
    if [ "$STATUS" = "error" ]; then
      die "Import job errored. Check: bin/kamal app logs -d local"
    fi
    if [ "$i" = 180 ]; then
      die "Import job timed out. Check: bin/kamal app logs -d local"
    fi
    sleep 1
  done

  info "Smoke: thumbnail serves"
  ASSET_ID=$(curl -fsS -H "Accept: application/json" "http://localhost/catalog/overview" \
    | python3 -c "import json,sys; d=json.load(sys.stdin); print(d['context']['recent_imports'][0]['id'])")
  curl -fsS -o /tmp/kamal-local-thumb.jpg -w "    thumbnail HTTP %{http_code}\n" \
    "http://localhost/assets/$ASSET_ID/thumbnail"
  info "SMOKE OK"
}

status() {
  info "Kamal details"
  bin/kamal details -d local 2>&1 | head -40 || true
  info "Containers"
  docker ps --filter "name=photo_searchable_library_rails" \
    --filter "name=kamal-proxy" \
    --filter "name=kamal-local-registry" \
    --format "table {{.Names}}\t{{.Image}}\t{{.Ports}}" || true
  info "Volumes"
  docker volume ls | grep photo_searchable_library_rails || true
}

down() {
  info "Removing app, proxy, accessories, registry session"
  bin/kamal remove -d local -y 2>&1 || true
  if docker inspect "$REGISTRY_CONTAINER" >/dev/null 2>&1; then
    info "Removing throwaway registry"
    docker rm -f "$REGISTRY_CONTAINER"
  fi
  docker volume rm "${SERVICE}_models" >/dev/null 2>&1 || true
  info "DOWN OK"
}

cmd="${1:-help}"
case "$cmd" in
  preflight)  preflight ;;
  up)         preflight; write_config; ensure_registry; push_sidecar; deploy_app; smoke ;;
  smoke)      smoke ;;
  status)     status ;;
  down)       down ;;
  help|-h|--help) sed -n '2,10p' "$0" ;;
  *) die "unknown subcommand '$cmd' (use: preflight | up | smoke | status | down)" ;;
esac
```

- [ ] **Step 1: Run the harness end to end**

Run:
```bash
script/kamal-local.sh up
```
Expected, in order:
1. `Preflight OK` (SSH, ports 80/5555/9090 free, `RAILS_MASTER_KEY` set).
2. `config/deploy.local.yml` generated with `ssh.user: jobofish`.
3. Throwaway registry up on `:5555`, `/v2/` answers.
4. Sidecar image builds (amd64; several minutes) and pushes.
5. `bin/kamal deploy -d local` succeeds — app image builds+pushes, proxy boots,
   app boots; proxy healthcheck `/up` turns green.
6. `bin/kamal accessory boot sidecar -d local` succeeds.
7. Smoke: `/up`, `/catalog/overview`, upload → job `done` → thumbnail HTTP 200.
8. Final line: `SMOKE OK`.

- [ ] **Step 2: If Docker rejects the plain-HTTP registry**

Docker Desktop may refuse `docker push localhost:5555/...` with an
"insecure registry" error (it should allow loopback by default; if it does not):

```bash
cat <<'JSON' > /tmp/daemon-override.json
{
  "insecure-registries": ["localhost:5555"]
}
JSON
sudo cp /tmp/daemon-override.json /etc/docker/daemon.json
sudo kill -SIGHUP $(pgrep -f "com.docker.backend" | head -1) 2>/dev/null || echo "restart Docker Desktop manually"
```
Then rerun Step 1. If `daemon.json` already exists, merge the
`insecure-registries` key instead of overwriting.

- [ ] **Step 3: If the import job fails to reach the sidecar (contingency B)**

The import job errors with something like `Failed to open TCP connection to
'sidecar'` or `Couldn't resolve 'sidecar'`. This happens because Kamal names the
accessory container `photo_searchable_library_rails-sidecar`, so the Docker DNS
name `sidecar` does not exist on the `kamal` network.

Confirm with:
```bash
bin/kamal app logs -d local 2>&1 | tail -20
```
If it shows a connection error to `sidecar`, edit `config/deploy.yml` — change:

```yaml
    PICS_WORKER_URL: http://sidecar:9090
```

to:

```yaml
    PICS_WORKER_URL: http://photo_searchable_library_rails-sidecar:9090
```

Then rerun Step 1.

Only if Step 3 applied:

